# SNS 素材驱动的分镜

从 v5（箱根ガラスの森美術館，2026-09-28）起，分镜不再先按场地写好、再去找相似的帖子对照，而是反过来：先在小红书、Instagram、抖音、TikTok 上找到这个场地真实出过片的机位和姿势，每张分镜从一条素材出发，照原帖的机位、焦段、构图和姿势设计同款；素材覆盖不到的地方再补分镜。这样示意图与原帖的对应关系是确定的，现场也知道每张要对着哪条帖子拍。

## 1 能做与不能做

- 浏览：Claude in Chrome，用用户已登录的账号，人工级速度，一次只开一篇；遇到风控（小红书 300031、登录弹窗、验证码）就停下，不绕过。
- 不抓图：不下载、不截图、不用任何工具（包括 Codex、系统截图）保存原帖图片，也不把原帖图片交给生图模型做参考或 edit 输入。
- 看图写字：Claude 在浏览器里看原帖，把机位、构图、人物在画面里的位置与大小、前景背景、姿势、穿搭、天气光线写成文字，记进 `sns_refs.json`。生图时 Codex 只收到这段文字。
- 原帖图片只在用户自己手里：用户想在私用版 PDF 里看原图时，手机扫码打开原帖、自己长按保存，放进 `plans/<plan>/sns_inbox/`，跑 `pipeline.py sns-import <plan>` 归到 `sns_private/<编号>.jpg`。`sns_inbox/` 与 `sns_private/` 都在 `.gitignore` 里，公开版（`--public`、examples、GitHub、发布页）一律不放。
- 生成的人物是原创成年女性，不描绘原帖本人的长相，只借用姿势、机位和构图。

## 2 调研时怎么记（sns_refs.json）

三类素材，编号前缀不同：

| 类型 | 编号 | 用在哪 | 必记字段 |
|---|---|---|---|
| 机位帖 | S01… | 复刻机位、焦段、构图（多半连姿势） | `platform` `url` `posted` `title` `stop`（对应路线停留点）`cam_bearing` `cam_dist` `cam_h` `lens_est` `kind`（景别）`frame`（人物中心横向位置 `x`、头顶 `top`、脚 `feet`，都按画面高宽的比例）`fg_bg` `pose_note` `outfit` `weather` `visual.composition / light / tone` `reproducible.level / why`，原帖写明或能判断时加 `device`（拍摄设备） |
| 姿势帖 | X1… 与其中的姿势 P01… | 一篇帖子里有多个姿势时拆成 P 编号，每个姿势分到一个合适的场景 | 帖子：`platform` `url` `posted` `likes` `title`；姿势：`name` `how`（一句话要领）`camera`（景别、方向、焦段）`scene`（适合放在哪） |
| 平台汇总 | Q1… | 小红书「问点点」这类对几十篇笔记的汇总，给出回廊、展厅这类地点的常见姿势 | 检索词、汇总篇数、搜索页链接、要点原文的摘要 |

写 `frame` 与 `visual.composition` 时按画面上的实际比例写，例如「人物中心在画面左侧约 42%，头顶在自上而下约 25%，下缘截在膝盖以下；右侧从近到远依次是石栏顶面、运河、玻璃雕塑、水晶框架」。这段文字后面会原样进 prompt，写得越具体，示意图与原帖越接近。

按设备搜：检索词在「<地点> 拍照 / 机位 / 出片」之外，按用户设备清单（`meta.gear`）里的每台设备各搜一轮，例如「<地点> GR4」「<地点> pocket3」「<地点> 索尼A7M5」「<地点> iPhone 人像」。用户有同款设备的机位帖优先复刻，因为焦段、画幅和成像观感能对上；设备不同时在 `reproducible.why` 写换算，例如「原帖 GR 28mm 定焦，用 24-105 的 28mm 端，站位不变」。分镜里照这条帖子设计的那张，`device` 写同一台。

季节或活动不同、今天复现不了的帖子（例如冬季圣诞树）保留在 `sns_refs.json` 里、`shots` 留空，只作穿搭参考。

## 3 从素材到分镜（shotlist.json 的 src）

1. 先列素材清单：每条机位帖一张分镜；姿势帖里的姿势按场景分到停留点，一个姿势一张；汇总里的姿势补在同一停留点。
2. 每张分镜写 `src`（字段见 `templates/shotlist_schema.json`）：`ref`、`kind`、`platform`、`title`、`url`、`posted`、机位帖的 `level` 与 `why`、姿势帖的 `likes` 与 `pose_id / pose_name / pose_how`、`what`（照搬了机位、焦段、构图、姿势中的哪些），同一张还借用了别的素材写进 `also`。
3. 机位、景别、焦段、`camera`、`subject`、`action` 都照原帖写；与原帖不同的地方（今天下雨、人物换成背影开场、加一个动作）写在 `what` 或 `why` 里说清楚。
4. 素材不够的地方再补分镜：开场与收尾的过渡、细节特写、连拍、短片、手机实况，`src` 写 `{"ref": "", "kind": "无 SNS 素材", "what": "补充分镜：…"}`。补完仍要过 `lint`（景别配比、焦段三档、首尾角色、相邻不重复）。
5. 路线排好后跑 `pipeline.py renumber <plan>`，编号改成游览顺序（01 是进门第一张），每张的时段按停留点的到达—离开时刻均分；备选排在最后。脚本会列出正文里还引用旧编号的地方（「改 16 室内」这类），手改。

## 4 写 prompt

- 先写 `scene_bible.md`：场地的真实样子（建筑材质与颜色、桥与栏杆的形制、水晶框架的高度与形状、水面与雕塑的位置、九月底植被状态），并列出容易被画错的东西（例如「不要石砌长拱廊」「不要黑色铁艺桥栏」）。场景词链与负面词都从它来。
- 每张 prompt 的取景段直接用 `sns_refs.json` 的 `frame` 与 `visual.composition` 文字；姿势段用 `src.pose_how`；风格、人物、服装、成像词链全组固定。
- 只用文字，不加参考图。检查时对照 `sns_refs.json` 的描述看构图是否一致，不一致就改写取景段重出。

## 5 页面上怎么呈现

- 分镜卡（`make_cards.py`）：有 `src` 时左侧只放一张示意图，中间是来源栏：素材类型与可复现度、平台与日期、原帖标题、原帖二维码（平台汇总是搜索页二维码）、照搬了什么、同款姿势要领、也参考、现场差异、链接。补充分镜的来源栏写「无 SNS 素材」和这张的作用、形式、景别。
- 核对表（`checklist.py`）：每条分镜下面一行来源，点标题在新页面打开原帖。
- 分镜都带 `src` 时，不再单出「SNS 参考机位」汇总页；姿势参考页也不再出，姿势已分到各张。旧企划（没有 `src`）仍按原来的方式出这两类页面。
