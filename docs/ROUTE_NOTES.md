# 路线：景点之间怎么排，景点里面怎么走

两层：一日多景点的「行程页」（`trip.json` → `cards/trip_01.png`），单个景点内部的「路线页」（`meta.route_stops` → `route.json` / `cards/route_01.png`）。小抄 PDF 的顺序固定为 行程 → 穿搭 → 路线 → 分镜（按路线顺序）。

## 1 景点之间（行程页）

- 写 `plans/<主plan>/trip.json`（模板 `templates/trip_template.md`）：起点、各景点、终点，每段交通的方式 / 线路 / 发到时刻 / 分钟 / 来源。
- 顺序依据，按优先级：营业时间与最后入场；每个景点最好的光线时段（`sun.md`，逆光张排在对应时刻）；交通班次（NAVITIME / 官网时刻表 / Google Maps，注明查询日期）；地理顺路（同一条线路上按站序）。
- 备选景点标 `optional: true`，行程页画灰点，正常日程不去。
- 行程页地图是按真实经纬度等比的示意图，连线为直线；不画道路，班次以出发当天查询为准。

## 2 景点内部（路线页）

- 在 `shotlist.json` 的 `meta.route_stops` 写停留点顺序，每站列分镜 id（拍摄顺序）与一句备注；`meta.route_source` 写依据（官网 園内マップ / 順路、小红书或官方博客攻略、当天预报）；`meta.route_speed_mps` 步行速度（默认 1.0，雨天 0.85）。
- `pipeline.py route <plan>`（`cards` 阶段会自动跑）把每站第一条分镜的 `subject_latlon` 吸附到底图步道，沿步道找两站之间的最短路，算距离与分钟，按介质估停留（静态 8 / 连拍 4 / 短片 4 / 实况 1 分钟，每站加 2 分钟），推出到达与离开时刻，画在风格化底图上。步道不连通时画直线并标「概略」。
- 顺序依据：官网设施顺序或 順路 → 攻略里的「先拍哪里」（人少、光好）→ 天气（雨大时段进回廊、展厅、檐下）→ 地理最短路。终点放在离出口近的位置，收尾分镜放最后。
- 没写 `route_stops` 时按每条分镜 `time` 的起点自动排序，同一 `spot` 合并成一站；仍会画路线页。
- 路线页的时刻是估算，`timeline.md` 里交通班次、最后入场、回程班次以它为准；两者冲突时改 `route_stops` 重跑。
- 多底图的场地（南北两张、园外备选点）只对 `--basemap`（默认 main）上的分镜算路线，其它底图上的分镜排在最后。分镜跨几张底图但要一页画完全程时，另做一张覆盖全程的总览底图（例：`basemap <plan> --name route --meters 640`），在 `meta.route_basemap` 写它的名字，`cards` 阶段的路线页就用它。
- 分镜的 `time` 已经按光线与活动时刻排好时，写 `meta.route_timing: "shots"`：每站停留按本站分镜的时间窗（最后一条结束 − 第一条开始），离开不早于最后一条结束；停留点可单独写 `dwell_min`。`meta.route_start` 是第一站的到达时刻（出站后还要走一段时用，缺省用 `meta.arrive`）。路线页终点时刻要早于离开的班次。

## 3 输入从哪里来

- 官网：`園内マップ` / `フロアマップ` / `施設案内` / `モデルコース`，常是 PDF 或图片，读出设施顺序即可，不要把官方地图放进小抄（版权），路线页用我们自己的底图。
- 小红书 / 官方博客：搜「<景点> 攻略」「<景点> 路线」，看「先去哪 / 几点去哪」的说法，写进 `route_source`。
- 交通：NAVITIME（日本巴士与电车最准）、官网时刻表、Google Maps；每段写查询日期。
